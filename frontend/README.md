# 1gnition

What NASA's microgravity fire data can actually support, before a Moon base relies on it.
NASA Space Apps 2026, Flame in Freefall challenge.

## Run it

- **Quickest:** double-click `index.html`. It uses the bundled copy of the data (`data/seed.js`).
- **Like the real site:** from this folder run `python3 -m http.server 8000`, then open http://localhost:8000. It reads the JSON files in `data/`.

## Put it online (GitHub Pages)

1. Create a GitHub repository and upload everything in this folder.
2. In the repository: Settings, Pages, Source "Deploy from a branch", branch `main`, folder `/ (root)`, Save.
3. After a minute the site is at `https://<your-username>.github.io/<repository-name>/`.

## Folders

| Path | What it is |
|---|---|
| `index.html` | page structure |
| `css/style.css` | all styling |
| `js/config.js` | data source, API and AI settings, tolerances |
| `js/data.js` | loads and validates the data |
| `js/logic.js` | ranking, applicability, comparison and gate rules (no AI) |
| `js/app.js` | the views, guided demo, Ask panel and provenance popovers |
| `data/*.json` | the data. Format in `DATA_CONTRACT.md` |
| `data/seed.js` | generated copy of the JSON for opening from disk |
| `tools/make_seed.py` | rebuilds `seed.js` after editing JSON |
| `tools/check-matching.cjs` | JS regression test for matching and comparison logic |
| `tools/acceptance_ui.py` | browser acceptance test (41 checks) |
| `docs/` | scientific methodology and decision notes linked from the site |

## For the data and backend team

Read `DATA_CONTRACT.md`. The five science files in `data/` are generated by `backend/service/build_frontend_data.py`; don't edit them by hand. Add rows to the hand-curated JSON files (or point `js/config.js` at the API in `backend/service/server.py`) and the counters, rankings, coverage grid and Data page update on their own. After editing JSON, run `python3 tools/make_seed.py`.

## Honesty rules the site follows

- Every measured number shows its source, location, read method and number of checks.
- Nothing is simulated. The burn replay moves at a published average rate.
- Rankings and tolerances are design choices and are labeled. No NASA spread-rate prediction is shown: the backend reports VALIDATION_NOT_SUPPORTED.
- Synthetic verification data is fenced off behind a SYNTHETIC — NOT NASA DATA banner and never mixed with NASA records.
- The Ask panel uses offline rule-based answers, clearly labeled, until the AI backend is connected.
- PSI record numbers are marked "link not verified" until someone opens them.

1gnition is a student project. It is not a NASA product and not a fire-safety certification tool.

## Photos (img/)
All photographs are NASA images, saved in `img/` so the site works offline and on any host.
The list, with NASA image IDs and credit lines, lives in `js/art.js` (`A.PHOTOS`) and is shown
in the footer under "Photo credits". To swap a photo, replace the file and update that entry.
NASA imagery follows NASA's media usage guidelines: credit NASA, do not use the NASA logo,
and do not imply NASA endorses the project.
