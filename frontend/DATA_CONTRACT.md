# 1gnition data contract

This is the agreement between the front end and the data/backend team. If your files or API follow it, the site shows your data with no front-end changes.

The site reads 16 collections. Each one is a JSON file in `data/` (or an API endpoint, see "Connecting the backend" below). The first 8 are the hand-curated legacy collections; the last 8 are generated by `backend/service/build_frontend_data.py` from the science package and must not be edited by hand.

| Collection | File | Shape |
|---|---|---|
| meta | `data/meta.json` | one object |
| sources | `data/sources.json` | list of rows |
| investigations | `data/investigations.json` | list of rows |
| runs | `data/runs.json` | list of rows |
| spread_rates | `data/spread_rates.json` | list of rows |
| findings | `data/findings.json` | list of rows |
| flags | `data/flags.json` | list of rows |
| predictions | `data/predictions.json` | legacy, kept empty; not rendered (see below) |
| scientific_comparisons | `data/scientific_comparisons.json` | one object, exported by `ignis_ml.science` (canonical Olson Table 1, 3 cases, factorial readiness, cross-source claims) |
| synthetic_verification_results | `data/synthetic_verification_results.json` | one object; SYNTHETIC, never NASA data |
| synthetic_model_benchmark | `data/synthetic_model_benchmark.json` | one object; M0/M1/M2 MAE on invented data only |
| evidence_catalog | `data/evidence_catalog.json` | list of every evidence item, each tagged with `evidence_class` |
| build_manifest | `data/build_manifest.json` | one object: input/output SHA-256, check results, `prediction_cm_s: null` |
| source_conflicts | `data/source_conflicts.json` | one object, copied from the science closeout kit: value disagreements and probable record aliases |
| brand_copy | `data/brand_copy.json` | one object: approved hero lines, tagline, qualifier, assistant disclosure |
| science_project_status | `data/science_project_status.json` | one object: the Scientific Lead's status record (not rendered) |

**Rules for every row**

- `id` is unique inside its collection and never changes.
- Units are in the field name: `_pct` percent, `_kpa` kilopascals, `_cm` centimeters, `_cm_s` centimeters per second, `_mm_s` millimeters per second, `_s` seconds.
- Unknown values are `null`. Never guess and never fill in Earth values.
- Every measured value carries a `provenance` object (below). Rows without one are flagged on the Data page.
- Do not put API keys, passwords or personal data in any file.

## provenance (inside runs and spread_rates)

| Field | Type | Meaning |
|---|---|---|
| `source_id` | string | `id` of a row in sources |
| `location` | string | Where in the source, e.g. `"Table 2, printed p. 8"` or `"Figure 10"` |
| `method` | `"table"`, `"text"` or `"digitized"` | How the value was read. `digitized` means read off a plot, so give `uncertainty` |
| `checks` | integer | How many people independently checked the value. 2 or more is the goal |

## sources

| Field | Type | Example |
|---|---|---|
| `id` | string | `"saffire_i_v"` |
| `title` | string | `"Saffire I–V paper, ICES 2021-266"` |
| `url` | string | link to the PDF or record |
| `type` | `"paper"`, `"slides"`, `"psi"`, `"brief"` or `"web"` | |
| `note` | string | what is used from it |

## investigations

| Field | Type | Meaning |
|---|---|---|
| `id` | string | e.g. `"bass"` |
| `name` | string | display name |
| `psi_id` | string or null | e.g. `"PSI-25"` |
| `psi_source_id` | string or null | sources row for the PSI record |
| `psi_confirmed` | boolean | true once someone has opened the PSI record and checked it |
| `pillars` | list | any of `"prevention"`, `"detection"`, `"suppression"` |
| `fuel_type` | string | `"solid"`, `"liquid droplet"`, `"gas"`, `"gas burner"` or `"smoke"` |
| `objective` | string | one sentence |
| `materials` | list | material codes: `"SIBAL"`, `"Cotton"`, `"PMMA"`, `"Nomex"`, `"Silicone"` (add new codes freely) |
| `materials_note` | string | sizes and details in words |
| `apparatus`, `sensors` | string or null | |
| `outcomes` | list | any of `"steady_size"`, `"spread_rate"`, `"smoke"`, `"extinction"` |
| `o2_pct_range` | `[min, max]` or null | tested cabin oxygen. Do not put burner oxidizer streams here (use `caution`) |
| `pressure_kpa_range` | `[min, max]` or null | tested total pressure |
| `gravity` | list | any of `"micro"`, `"lunar"`, `"mars"`, `"earth"` |
| `dataset` | object or null | `{ "size_note": "about 40 GB", "file_types": ["video", "thermocouple CSV"] }` |
| `caution` | string or null | anything that makes a comparison misleading |
| `source_ids` | list | sources rows |

## runs

One row per test run. Example:

```json
{
  "id": "I-1", "investigation_id": "saffire_1_3", "flight": "Saffire-I",
  "material": "SIBAL", "gravity": "micro",
  "airflow_cm_s": 20, "o2_pct": 21, "pressure_kpa": 100, "duct_height_cm": 46,
  "sample_width_cm": 41, "sample_length_cm": 94, "flow_direction": null,
  "steady_size_cm": 4, "max_size_cm": 6.2, "uncertainty_cm": null, "repeats": null,
  "provenance": { "source_id": "saffire_i_v", "location": "Table 2, printed p. 8", "method": "table", "checks": 2 }
}
```

## spread_rates

One row per spread-rate value. This is what the Scale Transfer Lab needs most.

| Field | Type | Meaning |
|---|---|---|
| `id` | string | |
| `run_id` | string or null | matching runs row, if any |
| `investigation_id` | string | |
| `series` | string | configuration as named in the source, e.g. `"BASS concurrent, 2 cm wide"` |
| `material`, `gravity` | string | as in runs |
| `sample_width_cm` | number | |
| `flow_direction` | `"concurrent"` or `"opposed"` | |
| `o2_pct`, `pressure_kpa`, `airflow_cm_s` | number or null | |
| `rate_mm_s` | number | the value |
| `uncertainty_mm_s` | number or null | required when `method` is `digitized` |
| `duration_s` | number or null | burn time, if the value is an average |
| `kind` | `"steady"`, `"average over burn"` or `"instantaneous"` | |
| `provenance` | object | see above |

The Transfer Lab gate passes when there are at least 6 rows from at least 3 flights or campaigns, more than one configuration, both small (under 10 cm) and large samples, and full units and provenance on every row. Thresholds live in `js/config.js`.

## findings

`{ "id", "text", "source_id", "location", "state": "published" }`. A paraphrased statement from a source, shown with its citation.

## flags

`{ "id", "severity": "conflict" | "check", "title", "detail", "applies_to": [row ids], "source_ids": [...] }`. Use these when two sources disagree or a value needs re-checking. The site shows them next to the affected runs.

## predictions (legacy)

Kept for compatibility and left empty. The site no longer renders it. The real prediction state comes only from `scientific_comparisons.prediction_status` (currently `VALIDATION_NOT_SUPPORTED`, `prediction_cm_s: null`). The old `GATE` row/flight thresholds in `js/config.js` are a heuristic and never unlock a prediction.

## Science collections (generated)

Rebuild them with `python3 backend/service/build_frontend_data.py --frontend frontend` from the repository root. The script re-exports from `backend/ignis-ml/data/revision`, runs 62 acceptance checks, and refuses to write if any fail.

`scientific_comparisons.json` follows `backend/ignis-ml/docs/SCIENCE_FRONTEND.md`. Key fields the site uses:

- `table1_records[]`: `record_id`, `flight`, `material`, `sample_width_cm`, `sample_length_cm`, `duct_full_height_cm` (Olson's full height; never mixed with Urban's `duct_height_cm` label), `oxygen_vol_pct`, `pressure_kpa`, `flow_cm_s`, `spread_cm_s`, `flame_length_cm`, `pyrolysis_length_cm` (null where unreported), `source_id`, `source_locator`, `approved_for_ml` (all false).
- `comparison_cases[]`: `baseline`, `comparison`, `measurements` (arrays ordered `[baseline, comparison]`), `difference_cm_s`, `ratio`, `percent_change` (denominator = baseline), `source_locations`, `comparability[]`, `confounding_warning`, `interpretation: "descriptive_only"`.
- `factorial_readiness`: `cells[]` with `historical_ids`, `missing_configuration`, `hypothesis_status: "UNTESTED"`, `interaction_cm_s: null`, `interval_cm_s: null`, `reason`, `protocol`.
- `alternative_source_claims`: the 23 Figure 10 markers and 2 PSI-99 entries. All have `count_as_additional_run: false`; they are cross-references, never extra rows.

`source_conflicts.json` drives the "Conflicting" column on Compare Runs and Scale Transfer, the Data → Source conflicts tab and the Research Gaps conflict count. Each conflict has `conflict_id`, `type` (`source_value_disagreement` or `candidate_record_alias`), `claims[]` (each with `source_id`, `source_locator`, `url`, and `value` or `record_id`/`candidate_record_id`), `match_status`, `resolution_status`, `display_message`, and `count_as_additional_independent_run` / `approved_for_ml` (both false). The site shows every claim separately and never picks one. A claim is linked to a Table 1 record through `run_identifier`, `record_id` or `candidate_record_id`. To add a conflict, add it to `research/closeout_kit/data/source_conflicts.json` and rebuild: no code change is needed.

`brand_copy.json` fills the hero (`hero_line_1`, `hero_line_2`, `product_name_line`, `tagline`, `scientific_qualifier`) and the Ask panel disclosure (`assistant_disclosure`). The HTML holds the same text as a fallback.

`evidence_catalog.json` rows: `{ id, evidence_class, source_scope, record, source_id, source_location, outcomes?, counts_as_independent_run?, is_nasa_data? }` where `evidence_class` is one of

| evidence_class | Meaning | Shown as |
|---|---|---|
| `published_numeric` | Printed in a published table (Olson T1, Urban T2) | blue "Published number" |
| `digitized` | Read off a published plot (Figure 10) | gold "Digitized estimate" |
| `archive_claim` | Recorded in a NASA PSI archive table | violet "Archive claim" |
| `derived_comparison` | Arithmetic on two published numbers | teal "Derived comparison" |
| `proposed_experiment` | A design that has not been run | orange "Proposed, not run" |
| `synthetic` | Invented data for software checks | pink "Synthetic, not NASA" |

## Connecting the backend

Everything is in `js/config.js`:

- **Static files (default):** edit the hand-curated JSON in `data/`, run the build script above for the science files, then `python3 tools/make_seed.py` so the page still works when opened straight from disk.
- **API:** run `python3 backend/service/server.py --frontend frontend` and set `DATA_MODE: "api"`, `API_BASE: "http://localhost:8787/api"`. The site calls `GET {API_BASE}/runs`, `/sources` and so on; each endpoint returns the same JSON as the matching file. Optional collections that are missing do not break the page.
- **Scenario check:** set `PREDICT_ENDPOINT: "http://localhost:8787/api/predict"`. The NASA prediction tab then sends the scenario as `backend/ignis-ml/docs/request.schema.json` and renders the `response.schema.json` reply. With no reviewed model the reply is always `LIMITED_EVIDENCE` or `UNSUPPORTED` with a null number, and the site refuses to display a number even if one arrives.
- **AI:** set `AI_ENDPOINT`. The Ask panel sends
  `POST { "question": "...", "scenario": { "material", "outcome", "o2_pct", "pressure_kpa", "gravity", "airflow_cm_s" }, "context": { "runs", "spread_rates", "findings" } }`
  and expects
  `{ "answer": "...", "state": "pub" | "expl" | "eval" | "insuf", "citations": [{ "source_id", "location" }] }`.
  The answer must use only the records in `context` and say insufficient evidence when they do not cover the question. Keep the API key on the server. No AI service is deployed. "Ask 1gnition" is an offline rule-based evidence helper, not a generative AI assistant, and the panel says so.

The server must allow requests from the site's address (CORS) if the two are on different domains. `server.py` reads allowed origins from `IGNITION_CORS_ORIGINS`.
